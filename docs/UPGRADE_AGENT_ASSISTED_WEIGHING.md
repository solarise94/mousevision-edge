# Agent 辅助称重系统升级设计

> 状态：设计草案。目标是先恢复可控生产，再通过真实数据逐步替换昂贵且不确定的 Agent 判断。

## 实施状态（2026-07-20）

第一阶段安全闸门已实现：

- Agent prompt 要求稳定平台、至少三条带时间戳的逐帧证据以及鼠/LCD 可见性。
- 本地解析器计算证据中位数，检查时间分散、窗口越界、多峰和最终值偏离。
- 本地视频再次按窗口采样，使用现有 OCR 构建独立时间序列；报告照片以本地稳定簇而非 Agent 目标值选取，避免循环验证。
- 缺证据、多峰、Agent/证据不一致、本地 OCR 不一致或照片中鼠缺失均转为 `requires_manual_weight`。
- Agent 记录延迟到全部证据闸门结束后才入队；人工记录不进入上传队列。

样本 `new_0720_run.mp4` 的实测依据已固化为回归：第 5 段单帧 `23.98g` 不得覆盖 `23.48–23.50g` 稳定簇。

## 1. 结论

系统不再把“鼠检测、会话切分、LCD OCR、最终裁决”绑在一条不可解释的状态机里。升级后采用三层架构：

1. **确定性数据层**：保存原视频、按 PTS 解码、生成候选区间和证据帧；它不猜最终读数。
2. **Agent 裁决层**：只分析候选区间，返回严格 JSON 的时间轴、读数候选、证据和不确定性。
3. **发布闸门层**：本地规则校验 Agent 结果；无法证明可靠的结果进入人工队列，不自动发布。

Gemini 是可替换的教师与疑难样本处理器，不是系统唯一真相源。所有结果必须能追溯到原视频、时间戳和证据帧。

## 2. 升级目标与非目标

### 目标

- 先让生产流程可用：不丢视频、不静默产生错误记录、不因模型失败阻塞整批任务。
- 将时间轴切分与 OCR 解耦，使任一模块都能单独回放和替换。
- 用 Agent 快速建立高质量标注集，同时控制费用、延迟和模型漂移。
- 小 OCR 只有在离线盲测与影子运行通过后才获得自动裁决权。

### 非目标

- 首期不追求全自动；宁可进入人工队列，也不自动发布错误体重。
- 不让 Agent 直接写数据库、删除素材或执行 ffmpeg。
- 不用连续相邻帧数量冒充独立训练样本数量。
- 不在生产请求中在线训练模型。

## 3. 目标架构

```text
Upload
  -> Immutable Raw Video + SHA256
  -> ffprobe/PTS validation
  -> Candidate Window Generator
  -> Evidence Pack Builder
       -> Local OCR (shadow/candidate)
       -> Gemini Agent (teacher/fallback)
  -> Decision Gate
       -> Auto Accepted
       -> Needs Review
       -> Rejected/Failed
  -> ffmpeg clip by validated PTS
  -> Record + Audit Manifest
  -> Training Dataset Builder
```

### 3.1 确定性数据层

输入为上传后的不可变原视频。输出为候选会话，不输出最终真值。

- 用 ffprobe 校验容器、H.264、时长和视频流。
- 使用解码帧 `pts_time`，禁止用 `frame_index / fps` 作为主时间轴。
- 原视频按 SHA-256 寻址；重复提交必须幂等。
- 粗检测只扩大召回率：生成可能的上秤区间，并在前后各增加保护窗口。
- 每个候选区间生成 evidence pack：代表帧、LCD crop、normalized strip、现有 OCR 逐帧观测、检测框和质量指标。
- 无论后续成功与否，都保留原视频和 manifest。

### 3.2 Agent 裁决层

Agent 只接收候选窗口或压缩后的证据包，避免每次上传完整视频。

Agent 必须：

- 找到小鼠明确进入、稳定称重和离开的时间。
- 在多个证据帧上独立读取 LCD。
- 报告候选读数分布，而不是只给一个答案。
- 明确报告遮挡、手套、反光、负号、跳数和无法判断。
- 只返回符合版本化 JSON Schema 的数据。

建议输出：

```json
{
  "schema_version": "weighing-agent/v1",
  "model": "configured-model-id",
  "sessions": [
    {
      "candidate_id": "candidate-0001",
      "start_ms": 12340,
      "stable_start_ms": 15100,
      "stable_end_ms": 17800,
      "end_ms": 19620,
      "weight_text": "18.91",
      "weight_grams": 18.91,
      "evidence_ms": [15800, 16400, 17100],
      "frame_votes": ["18.91", "18.91", "18.91"],
      "mouse_present": true,
      "display_consistent": true,
      "occlusion": "none",
      "confidence": 0.97,
      "review_reasons": []
    }
  ]
}
```

Agent 的自然语言解释只用于日志，不能驱动程序行为。解析失败、字段缺失或 schema 不兼容均 fail closed。

### 3.3 发布闸门层

自动发布不是由单一 `confidence` 决定，而由可解释规则共同决定：

- 至少三个时间分散的证据帧给出完全相同的读数。
- Agent、当前规则 OCR 和后续小 OCR 中至少两个来源一致；首期可要求 Agent 与人工一致后再发布。
- 时间区间合法、不重叠、不越过视频 PTS 范围。
- 稳定段持续时间达到阈值，且鼠检测在稳定段成立。
- 无负号、无严重遮挡、无显著多峰读数冲突。
- 体重在项目配置的合理范围内；范围只能触发复核，不能擅自改值。
- 任一检查失败进入 `NeedsReview`，不得降级为自动接受。

建议统一状态：

```text
INGESTED -> CANDIDATES_READY -> AGENT_PENDING -> DECISION_PENDING
          -> AUTO_ACCEPTED | NEEDS_REVIEW | REJECTED | FAILED
```

发布队列只接受 `AUTO_ACCEPTED` 或经人工确认的记录。

## 4. 视频切片原则

- Agent 只返回时间计划；后端使用原视频和 PTS 执行切片。
- 首选 stream copy；关键帧不允许精确切点时重新编码，并在 manifest 中记录方式。
- 切片前验证 `start < stable_start <= stable_end < end`。
- 切片后重新 ffprobe，核对实际首尾时间与目标偏差。
- 任何切片失败不影响原视频与其他候选会话，单条进入 `FAILED`。
- 重跑不得生成重复记录，幂等键为 `video_sha256 + candidate_id + pipeline_version`。

## 5. 人工复核界面

复核页一次只解决一个问题：这个区间是否是一只鼠的一次有效称重，正确读数是什么。

页面应同时展示：

- 可拖动的原视频区间和稳定段。
- 三至五张证据帧及其 LCD 放大图。
- Agent、规则 OCR、小 OCR 的逐帧读数与分歧。
- 修改开始/结束时间、修改体重、标记误检/漏检/遮挡的入口。
- “确认”“拒绝”“拆成两个会话”“合并相邻会话”操作。

每次人工操作记录原值、修改后值、操作者、时间、原因和模型/管线版本，禁止覆盖历史。

## 6. 数据闭环与小 OCR

### 6.1 数据单元

训练数据的主键是独立称重会话，不是帧。每个会话保存：

- 原视频哈希和时间窗口。
- 真实 chosen strip/normalized screen。
- 完整字符串、字符槽标签、负号和小数点位置。
- 可读性、反光、遮挡、模糊、手套和过渡帧标签。
- 人工确认来源与修订历史。

稳定段相邻帧先按感知哈希或 SSIM 去重，每个会话只保留少量多样帧；困难帧另行保留。

### 6.2 模型路线

固定七段屏不优先训练通用端到端 OCR。采用：

1. 沿用屏幕定位和透视归一化。
2. 固定或可校准字符槽切分。
3. 小型 CNN 分别分类 `0-9/blank`；负号独立分类。
4. 输出每个字符的概率，禁止只输出拼接后的字符串。
5. 用时间维度投票和读数变化约束聚合，但多峰冲突必须转人工。

增强仅模拟真实变化：亮度、gamma、局部高光、轻微模糊、压缩噪声和小幅透视。不得使用会破坏七段几何意义的强形变。

### 6.3 数据量与拆分

现有四条视频只作为 bootstrap：三条训练/验证，一条整视频初测，不能随机按帧拆分。

取得生产自动裁决权前建议至少具备：

- 300–500 个独立称重会话。
- 覆盖至少五个日期、不同操作员和典型光照。
- 每个数字至少约 200 次独立出现。
- 单独覆盖反光、手套遮挡、运动模糊、负号和读数跳变。
- 一批完全未参与提示词调整和训练的新日期盲测视频。

数据集按 `video/day/cage` 分组拆分，严禁同一会话的相邻帧跨集合。

## 7. 模型晋级门槛

模型按以下阶段晋级：

1. **Offline**：只在冻结数据集离线评估。
2. **Shadow**：线上产生结果但不参与裁决，与人工/Agent 比较。
3. **Assist**：仅当与 Agent/规则一致时减少人工工作量。
4. **Primary**：满足盲测门槛后成为主要 OCR；Agent 只处理疑难样本。

至少评估：字符 macro-F1、完整字符串准确率、会话最终准确率、错误自动接受率、人工复核率、按光照/操作者/遮挡分层的结果。

生产门槛优先约束错误自动接受率。建议在不少于 300 个独立盲测会话中出现任何错误自动接受，就不进入 `Primary`；阈值可在真实风险评审后调整，但不能用平均字符准确率替代。

## 8. Agent 风险控制

- 固定 prompt、JSON Schema、模型 ID 和推理参数，并记录版本。
- 对相同 evidence pack 缓存响应；重试不得生成多条业务记录。
- 设置单视频调用次数、token、文件大小和总耗时上限。
- Agent 超时或不可用时进入人工队列，不能回退到未经验证的自动 OCR。
- 每日抽样复核自动接受记录，监控模型漂移。
- 若视频包含敏感信息，部署前完成数据出境、保留周期和访问权限确认。
- 提供 provider adapter，Gemini 可被其他 VLM 或本地模型替换。

## 9. 分阶段落地

### Phase A：生产止血

- 确认最新版管线真实部署，并提供 `/version` 或 build commit。
- 原视频不可变保存，所有新记录默认 Held/NeedsReview。
- 建立 evidence pack、Agent schema、Decision Gate 和审计 manifest。
- Agent 仅给建议，所有结果人工确认。

退出条件：不会静默丢会话；错误结果不会自动发布；任一记录可回放到证据帧。

### Phase B：Agent 辅助生产

- 候选区间批量提交 Agent。
- 支持结构化时间轴、后端切片、缓存、重试和费用监控。
- 对强一致结果开放有限自动接受，并持续抽检。

退出条件：在新日期盲测集上没有错误自动接受，且人工复核量可接受。

### Phase C：数据集与 OCR shadow

- 把人工确认结果固化为版本化数据集。
- 训练字符槽模型，建立可复现训练配置和冻结测试集。
- 在线 shadow，按会话比较 Agent、规则 OCR、小 OCR 与人工结果。

退出条件：达到既定盲测门槛，且没有明显分层退化。

### Phase D：本地 OCR 接管

- 小 OCR 成为主路径。
- Agent 仅处理低置信度、多峰冲突、遮挡及抽样质检。
- 持续主动学习，但新模型必须重新经过 Offline -> Shadow -> Assist 晋级。

## 10. 首批实施清单

按依赖顺序实施：

1. 部署可验证性：build commit、配置摘要、模型版本和健康检查。
2. `EvidencePack` 与版本化 manifest。
3. Agent provider 接口、Gemini adapter 和严格 JSON Schema。
4. Decision Gate 与统一状态/队列语义。
5. PTS 切片执行器及切后校验。
6. 人工复核页与不可变审计日志。
7. 数据集导出、去重、分组拆分和数据质量报告。
8. 小 OCR baseline、离线评估和 shadow 接入。

## 11. 必须覆盖的端到端测试

- Agent 返回非法 JSON、缺字段、超时和重复响应。
- 时间越界、会话重叠、VFR、负 PTS 和截断视频。
- 同一上传/重试只产生一组记录。
- Agent 与 OCR 冲突时始终进入人工队列。
- `18.91 -> 10.71`、`17.66 -> 11.61` 等历史错误固定为回归样本。
- 人工拆分、合并、修正、拒绝后的记录与训练资产一致。
- Agent 不可用时不丢视频、不错误发布。
- 模型或 prompt 版本变化后旧缓存不会误复用。

## 12. 决策摘要

- 四条视频：够做 baseline，不够授予生产自动裁决权。
- Gemini：作为教师、时间轴分析器和疑难 fallback，不作为不可审计的唯一生产路径。
- 切视频：后端按 Agent 给出的时间计划和真实 PTS 执行。
- 小 OCR：固定七段字符槽模型优先，经过完整的离线、影子和辅助阶段后再接管。
- 安全原则：原视频永不因分析失败而删除；不确定即人工；任何最终结果必须带证据。
